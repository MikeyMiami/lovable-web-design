# Marketing-Site TEMPLATE (style shell → client Remixes)

This project is a frontend-only marketing-site TEMPLATE. Per-client sites are exact REMIXES of it — this code is the master for every future client site of this style. Workspace rules apply, especially: frontend-only, data is LIVE, no service-role.

## The contract [LOCKED]
- **Platform connection = HARDCODED CONSTANTS in `src/lib/client-data.tsx`, NOT `.env` [LOCKED 2026-07-24].** `SUPABASE_URL`, the anon key, and the API host (`https://app.pierceworks.co`) are the same for every client forever, so they live as hardcoded constants (with an `import.meta.env.X ?? "hardcoded"` fallback). Deliberate: **Remix regenerates `.env` and strips `VITE_SUPABASE_*`**, so relying on `.env` = demo mode every remix. API host matters: the supabase origin 404s `/api/public/*` and lovable.app 302s (breaks CORS preflight) - only the app custom domain answers. `package.json` carries a `seroval` override so the first publish clears the dependency audit.
- **TWO per-remix `.env` values, set at DIFFERENT times.** (1) **`VITE_CLIENT_SLUG`** — at remix time; blank = demo mode. (2) **`VITE_SITE_URL`** — at DOMAIN DAY only, `https://theirdomain.com`, no trailing slash. Both are pre-declared in the template `.env` (pre-declared so the field shows in every remix). **`VITE_SITE_URL` is an INDEXING KILL-SWITCH:** while empty, `isIndexableOrigin()` returns false, every page serves `noindex,follow`, `/robots.txt` serves `Disallow: /`, and canonical/og:url fall back to the TEMPLATE's domain. Deliberate pre-launch protection - but forgetting it on domain day is a **silent total SEO blackout, no in-app warning**. Env bakes at PUBLISH: set it, republish, then verify from OUTSIDE with curl (robots meta, robots.txt, sitemap `<loc>`s, canonical). **NEVER put the client's domain in `VITE_PLATFORM_API_HOST`** — that is the BACKEND host and must stay `https://app.pierceworks.co`; overwriting it silently kills every form POST while the site looks perfect (happened 2026-07-27). One is where the site *talks to*, the other what it *calls itself*.
- NEVER hardcode a specific client's name, copy, phone, images, or data into code. Everything client-specific renders from live data at page load (`get_client_public` RPC + content-page RPCs + template_vars). The same code must serve ANY client.
- No DB writes, no service-role, no DB-touching server fns. Public writes = POSTs to `{VITE_PLATFORM_API_HOST}/api/public/*` only; the tenant is resolved server-side from the request Origin (the site's domain must be in the client's `allowed_origins`) — NEVER send client_id in a request body.

## Data the site renders (all LIVE per page load)
`get_client_public`: business identity (name, **`phone_display`** — the RPC's ONLY phone field; the template DERIVES `phone_e164 = toE164(phone_display)` in `client-data.tsx`; every `tel:` uses that, never the raw string (unparseable/blank -> phone_e164 null -> call UI hides). Render the visible number via `formatPhoneUS`, since `phone_display` only normalizes on a Settings save and can hold raw digits — hours, address), branding (logo_url, brand_color + `template_vars.brand_secondary/tertiary`), template_vars (**services: the DB key is `services_structured`** = `[{name,slug,description}]`, which `mapPublicRowToClient` maps to `template_vars.services` - READ `services`, WRITE/seed `services_structured`; **LOOP over it, never a fixed number of hardcoded cards**; `about_us`; `differentiators`; `lead_form_headline/subhead/cta`; `chat_widget_greeting/confirmation`; consent/category tokens), social_links, review config, `chat_widget_enabled`. `content_pages` rows drive the SEO pages - generic renderers (home/category/service/geo/supporting) + sitemap from the store.

**TWO demo flags — never merge them [LOCKED 2026-07-29].** `isDemoMode()` (`SLUG.length === 0`) also **gates the live data fetch** in `fetchClient()` — widening it makes the site render the built-in demo business instead of the real client. `isPreviewClient()` (`SLUG.startsWith("demo-")`) is submission-only, checked as `isDemoMode() || isPreviewClient()` in LeadForm / DiscountForm / ChatWidget. Why: agency Demo Clients mint `demo-{name}-{rand}` slugs; a remix pointed at one must render that prospect's REAL data while its forms stay inert (the backend 403s a demo tenant). Never put `isPreviewClient()` in `fetchClient()`'s guard.

## Forms (3: lead / discount / chat-optin) [LOCKED]
- ONE shared lead-form component drives BOTH the hero-embedded card and `/contact`. Phone REQUIRED, email optional. Copy from `template_vars.lead_form_*`.
- SINGLE consent checkbox (marketing skeleton), UNCHECKED + optional, verbatim a2p compliance copy; terms link → the on-site terms page.
- Invisible PoW bot-shield on ALL forms: mint at `{HOST}/api/public/challenge` -> solve in a Web Worker -> submit `pow_token` + hidden `website` honeypot. No visible widget. Missing shield = zero leads (backend fail-closed).
- Chat widget = capture-first lead form in a chat skin (NO AI); render the bubble when `chat_widget_enabled`; posts `/api/public/chat/optin` (consent REQUIRED there). ALSO opens on a window `"open-chat-widget"` CustomEvent - the hero CTA dispatches it. ONE widget, MULTIPLE triggers; never a second chat UI.
- Two site-wide conversion elements: a **Call-Now pill INSIDE the header**, centered between logo and nav (NOT a full-width strip, not mounted in the shells; `tel:` from `phone_e164`, number via `formatPhoneUS(phone_display)`, label = `home.call_bar_label`, renders nothing when `phone_e164` is blank, must stay reachable on mobile) and a **hero chat CTA button** at the bottom of the hero text block (label = `home.cta_button`, gated on `chat_widget_enabled !== false`).
- **HERO/H1 SPLIT [2026-08-02]:** the ONE `<h1>` holds the SEO keyword phrase (`page.h1` -> `hero_headline` -> `business_name`) but renders as a SMALL KICKER above the big line; the large serif display line is the `home.hero_headline` slot (blank = show H1 text there), with optional `home.hero_subhead` below it. Never make the display line an `<h1>`. Intro precedence: `home.intro` override -> published body's 1st paragraph -> default.

## Required pages
Home (hero + embedded lead form), Contact, Gallery, Thank You, Discount Funnel, Review Us, ToS, Privacy, SMS Program (compliance copy VERBATIM from the a2p source doc), the content_pages renderers, and **`/review/$token` → 302 → `https://reviewbatch.com/api/public/r/$token`** (the review-link redirect — never remove; it is what makes review SMS links work on the client's own domain). Footer on every page: named Privacy / ToS / SMS-Program links, socials, business identity.

## Copy slots (`src/lib/default-copy.ts`) [LOCKED]
`resolveCopy(slot, client)` = `template_vars.content[slot]` (agency override, Admin -> Content) **else** `buildDefault(slot, client)`, composed from live data. **No raw-display tier** - owner-typed `about_us`/`differentiators`/`tagline` are AI INPUTS, never rendered raw. **12 slots:** `home.intro` (was `home.hero_sub`; renders BELOW the hero - templates dual-read both), `home.services_intro`, `services.index_intro`, `about.overview`, `about.approach`, `contact.intro`, `gallery.intro`, `discount.sub`, MICRO-COPY `home.call_bar_label` ("Call Now") + `home.cta_button` ("Chat with us now"), HERO `home.hero_headline` + `home.hero_subhead`. The MICRO-COPY pair are the ONLY literal-string defaults - 2-5 word button labels, never interpolate business_name/city/services. The HERO pair use `copyOverride()` NOT `resolveCopy()` - no `buildDefault` case; they fall back to the H1 text and legacy `template_vars.hero_subhead`. **The slot registry is duplicated in THREE files** - change all or a slot half-works: this file + the app's `site-copy.functions.ts` (AI) and `admin.content.tsx` (form fields).

## Design
Theme from `brand_color` (+ secondary/tertiary) injected in the shell head; this template's style preset is its identity — keep its layout/spacing system consistent. Hero lead form: the header block owns the spacing to the form. No lorem/placeholder text in committed code — demo mode (blank slug) renders the demo dataset.
- **`html` needs a DARK background** (`styles.css`, with a matching `<meta name="theme-color">`; keep `body` on `--color-background`). iOS Safari paints the `<html>` background behind the status bar and in the pull-to-refresh overscroll area, and that region **stays pinned while the page scrolls** — with a light background it reads as a white bar above the header, on mobile only, with **no element in the DOM to find**. Do NOT add `viewport-fit=cover` to fix it: unnecessary here, and it pushes a `top-0` header under the clock/battery unless `env(safe-area-inset-*)` padding is added too.
- **Every flex ancestor between a card and truncating text needs `min-w-0`.** A flex item defaults to `min-width:auto` and refuses to shrink below its content, so one missing `min-w-0` makes text blow out past the frame and shove siblings off-screen — truncation silently stops working.
- **An inline `style` transform and a Tailwind transform class on the same element do NOT merge — the inline one silently wins.** A `group-hover:-translate-x-*` alongside an inline `translateX()` is dead code.

## Testing
In-editor iframe origins are ephemeral and CORS-blocked BY DESIGN — test forms only from the stable PUBLISHED origin, after adding it to the client's `allowed_origins` in the app's admin Settings. If client data renders blank: the slug is wrong, the client isn't `status='active'`, or the origin isn't allowlisted.
