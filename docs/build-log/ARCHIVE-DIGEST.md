## 1. Postgres / RLS / SECURITY DEFINER (the foundation lessons)

- **Never revoke EXECUTE on the RLS helper functions to silence the Supabase linter.** Postgres checks EXECUTE against the CALLING role at call time — `SECURITY DEFINER` does NOT exempt that check (it only sets whose privileges run inside the body). Revoking from `anon`/`authenticated` breaks ALL authed RLS evaluation (`permission denied for function`) — this actually happened (migration 3). The real boundary is the **in-body self-guard**: `IF auth.role() <> 'service_role' AND _user_id IS DISTINCT FROM auth.uid() THEN return false/empty`. The linter's 8 SECURITY DEFINER warnings on the 4 helpers are EXPECTED and deliberate — leave them. (migration-4-helper-execute-fix)
- **`CREATE OR REPLACE FUNCTION` does not inherit attributes** — re-declare `SECURITY DEFINER`, `STABLE`, `SET search_path = public` in every replacement or the hardening is silently lost. Guard return types: boolean helpers `RETURN false`; `user_client_ids` returns an EMPTY SET, not false. (migration-4)
- **Admin "check another user's access" must go through a service-role server fn** — the helpers are self-only for authed callers by design. (migration-4)
- **Any SECURITY DEFINER RPC callable via `supabaseAdmin.rpc` MUST re-run authorization in its own body, line 1** — a server-fn-side check alone is the "audited but unauthorized" escalation hole (found REAL on the role-grant RPCs: anyone reaching them could grant any role and it would be neatly audited). Defense-in-depth = fn check + in-RPC 1d-matrix check; `RAISE` aborts pre-mutation so rejected attempts (correctly) leave no audit row. Applied proactively to `export_client_bundle`. (stage-3.5b, stage-3.5c)
- **Audit pattern that held:** trigger-on-`user_roles` as SOLE writer = completeness floor (even direct SQL grants get audited, actor NULL/`direct_sql`); fn-context enrichment via `SET LOCAL` GUC (txn-scoped, pool-safe); audit-write failure → `RAISE WARNING` (visible), never silent swallow; immutability trigger blocks UPDATE/DELETE for all roles incl. service_role. **First admin is bootstrapped by direct SQL** (the authz matrix can't mint the first admin — chicken-and-egg). (stage-3.5b, stage-3e)
- **`export_client_bundle` enumerates tenant tables from `information_schema`** (BASE TABLES with a `client_id` column) — future tenant tables auto-include, no hardcoded list to drift; `%I`-quoted names + bound `$1` params. **Archive semantics [LOCKED]:** soft offboard (`status='archived'`+`deleted_at`), the runner stops at the CLAIM fn (it JOINs clients `status='active'` — future code paths can't forget it), data persists indefinitely; **no auto-purge exists — a PII retention/purge policy for long-archived clients is an open backlog item.** (stage-3.5c)
- **`onboarding_tokens.created_client_id` is deliberately NOT named `client_id`** — keeps the non-tenant table out of the `audit_tenant_rls()` scan. Naming a column `client_id` opts a table into the tenant-policy audit. (stage-c3d1)

## 2. Cron runner / drip engine — ⚠️ several items are LIVE AGAIN when the runner is re-scheduled

- **`claim_due_enrollments` final form** (proven): `ranked` (row_number PARTITION BY client_id) → `eligible` (≤25/client) → `locked` (`FOR UPDATE SKIP LOCKED` on base rows) → `leased` (`next_run_at = now()+5min` same tx), one statement/one snapshot. The lease prevents overlapping-tick double-claims; crashed-mid-tick rows self-heal after 5 min. (stage-1e)
- **⚠️ OPEN — at-least-once ⇒ possible duplicate SMS:** a tick crashing AFTER a real send but BEFORE advancing re-fires that step after the 5-min lease → one duplicate text. The recommended idempotency guard (before sending step N, check no `sms_sent` event exists for (enrollment, current_step)) was **never built**. Rare, accepted at stub-scale — **revisit at cron re-enable for real clients.** (stage-1e forward-note 1)
- **⚠️ OPEN — DST-gap window start:** a client setting `sms_send_window.start` inside their tz's spring-forward gap hour (e.g. 02:30) gets a ~1h-off window one day/year. 09:00 default is safe; **add a clamp if window start ever becomes freely UI-configurable.** (stage-1e forward-note 2)
- **Throughput ceiling:** `LIMIT 500 ÷ 25/client = 20 clients per tick` — at many simultaneously-bursting clients, drain spreads over several ticks (fairness holds, latency grows). Revisit `_limit`/K at scale. (stage-1e forward-note 3)
- **steps_json timing semantics — the two bugs that WILL recur if forgotten:** `offsetMinutes` = gap from THIS step → NEXT (so `step[0].offsetMinutes` is NOT the initial delay); `sequences.start_delay_minutes` (added column) = the pre-step-0 delay, read at ENROLLMENT (`next_run_at = now + start_delay`). And **`0` ≠ absent**: `offsetMinutes: 0` means "next step immediately"; ABSENT means terminal — a falsy-check (`step.offsetMinutes ? … : null`) silently truncated One-Year at SMS2/SMS5 and Missed-Call at SMS1. Both fixed; both semantics documented in scratch-foundation §7. (stage-2a, stage-2d)
- **Stub-validation blind spot:** the 0-offset bug was invisible in stub testing because the stub sequences had no 0-offset steps — surfaced only against the real seed. Rule: prove walkers/contracts against the REAL seeded shapes, not stub fixtures. (stage-1e/2a)
- **Caps in client-tz:** daily counts run from `startOfLocalDayUtc(now, tz)` (client-tz midnight, not UTC); in-memory count increments during the tick (no in-tick overshoot); blocked-cap reschedules to tomorrow's window-open. Blocked/deferred NEVER advances `current_step`. `template_missing` → event + `+15min` retry, step not consumed. (stage-1e, stage-3.5d)
- **The F-resolver incident (the worst latent bug of the build):** the runner's SMS branch originally never read `templates` at all — every drip SMS shipped the literal `[stub] <key>` body, invisible through ALL of Stage 2 because stage tests validated mechanics, not content; at go-live it would have texted `[stub] review_request_sms1` to real customers. Fix = shared `resolveTemplate(clientId,key)` (tenant-override → global) used by BOTH the notification dispatcher and the runner SMS render. **Standing regression rule: after ANY runner change, re-confirm "runner renders real bodies" across the FULL drip set** (real copy, merged vars, real tracked links, zero `[stub]`, zero literal `{…}`). (stage-3f)
- **Send primitive stays SEND-ONLY** (no DB writes, no event logging inside it); message materialization lives in the CALLERS via `insertOutboundMessage` — Admin variant (runner/service-role) + RLS variant (reply/authed). Outbound message status in stub mode = `'stub'` (chosen over `queued` because `queued` is also a real provider status). (stage-3a, stage-3c)
- **One-year reply-exit must be REAL-TIME at the inbound webhook** — a pre-step-only check delays the "they replied!" owner notification by up to the inter-step gap (~30–60 days = useless). Was a 1f forward-flag; **verify the (Telnyx) inbound path drives the exit + interest notification in real time as part of the cron-re-enable checks.** (stage-2e flag 5)
- **Day-10 reminder suppression semantics** (deliberate narrowing): suppresses when a `review_request` enrollment for the same (client_id, contact_id) exists with `created_at >= the lead enrollment's` — a contact ALREADY in the review drip BEFORE the web lead is NOT suppressed (rare; accepted). Rests on the contact model being phone-deduped per (client_id, phone). (stage-2e flag 2)
- **Single notification write path [LOCKED]:** `writeNotification` is the ONLY `notifications` insert; wrappers delegate; the chat-lead variant is a templateKey SWAP of the lead-form step (never an added write) → no double-notify. (stage-2c, stage-2e, stage-2f)

## 3. Public routes / funnel

- **Public pages MUST live under `/api/public/*`** — top-level routes inherit the app auth gate. The review funnel originally shipped at top-level `/r/*` and was a DEAD funnel for logged-out customers (302→auth). Anti-regression: never relocate public surfaces to top-level paths; this trap nearly recurred for the chat routes (spec named `api/chat.ts`) and was caught. (stage-2b, stage-2f F6)
- **Public-reachability proof standard:** an actual unauthenticated request against the PUBLISHED URL (curl/incognito) returning the handler's own response (302/200/Zod-400 + CORS headers) — NOT an auth-bridge redirect. Service-role SQL round-trips prove logic, never reachability. (stage-2b, stage-2f)
- **Click semantics [LOCKED]:** `events('review_clicked')` inserts PER LANDING (dashboard counter = total clicks); `tracked_links.clicked_at` stamps FIRST click only (funnel state / drip-exit / dedupe). Two different stamps, both intentional. (stage-2b, stage-3d)
- **Status flips on SUBMIT, not selection:** `review_completed` flips on rate-form submit (rating is re-selectable until then); `negative_review` flips on FEEDBACK-form submit (abandoned feedback ≠ marked negative). (stage-2b)
- **Token model:** onboarding links are single-use (claim-FIRST on submit), no time-expiry; slug-collision auto-resolves with a suffix; the public submit forces `status='pending'` server-side and ignores any client-sent status/client_id. (stage-c3d1, stage-c3d3)

## 4. Client-tz correctness (the pattern + the proof shape)

- **Boundary pattern:** `Intl.DateTimeFormat({timeZone})` reads the client's local Y/M/D/weekday → compute ISO-Monday week start + 1st-of-month as LOCAL wall-clock midnights → `fromZonedTime` each to a UTC instant (per-date offset = DST-safe) → compare `.gte(created_at, instant)`. Null/malformed tz → try/catch fallback to UTC with a VISIBLE "Timezone: UTC" header (never crash). (stage-3d)
- **The proof shape worth reusing:** seed a row inside the discriminating window between the UTC-naive cutoff and the correct local cutoff (e.g. `03:00Z` = Sun 23:00 NY, window `[00:00Z, 04:00Z)`) and assert it's EXCLUDED — one seed proves tz-correctness. (stage-3d)

## 5. Admin isolation rules (recur on every new admin surface)

- **The DETAIL-pane rule:** every by-id detail/sub-pane query must ALSO filter `.eq('client_id', activeClientId)` — for an ADMIN (whose RLS spans all clients) a stale selected-id under a new active client would render the OTHER client's record, and **queryKey invalidation does NOT save you** (the refetch still returns the row). Also reset open selections on client switch. (stage-3e)
- **Admin spans clients via the `is_admin()` RLS branch on an authed JWT — never service-role on read surfaces.** `is_admin()` covers both `admin` and `agency_owner`. (stage-3e)
- **React context must live in a shared module** (`@/lib/admin-context`) — importing a context from a route file forked it into duplicate instances and blanked `/admin` (infinite load). Grep-guard against stray `./admin` context imports. (stage-3e bug 1)
- **Global-seed protection shape:** per-client template/sequence edits upsert `{client_id: activeClientId, key}` with `onConflict:"client_id,key"` against PARTIAL unique indexes (`WHERE client_id IS NOT NULL`) — the global (`client_id IS NULL`) rows are structurally unreachable from that upsert; no `.update()`/`.delete()` by key alone. (stage-3f)
- **Reads that need global+override use `.or('client_id.is.null,client_id.eq.X')` + prefer-client picker** — the same precedence shape everywhere (templates, sequences, start-delay). (stage-3f)

## 6. Lovable / app-layer gotchas (each cost real debugging time)

- **Server fns must attach `statusCode` to thrown errors** — `errorMiddleware` swallows anything else and failures are INVISIBLE (no toast, no log). Pair every mutation caller with an `onError` toast. (stage-seo-store-3a)
- **The `<Toaster/>` host must be mounted at the root** — it wasn't, so every `toast()` across the entire app was a silent no-op for weeks (successes AND failures invisible). Verify the host exists before trusting toast feedback; keep a persistent inline "last run" line as belt-and-suspenders on critical actions. (stage-seo-store-3b)
- **AI structured output: keep the schema LOOSE** (names/strings only) — strict nested `generateObject` schemas with regex slugs fail ("No object generated"); derive slugs/shape/uniqueness server-side; always keep a `generateText` + `JSON.parse` fallback. (stage-seo-store-3a)
- **Anti-hallucination is prompt + DETERMINISTIC guards, never prompt alone:** PROVIDED-CONTEXT block + strict "only these facts, write around missing ones" rules + a **closed-set service list** ("write ONLY about listed services; never a typical-for-the-industry one" — the model invented snow removal for a landscaper without it) + deterministic post-passes (duplicate-H1 strip, leak scan, link guarantor). Every incident of AI non-compliance with a prose rule got a code guard. (stage-scope-hardening, stage-double-h1-strip, stage-seo-store-3c2)
- **Durable stored marker > content-shape heuristic** for UI state (e.g. `<!-- ai-written -->` comment vs "does it start with h2?") — derive state from persisted flags, not by re-parsing content. (stage-seo-store-3c2)
- **RPC param names must match the backend EXACTLY** — PostgREST resolves by named args; a mismatch (`p_client_slug` vs `_slug`) 404s SILENTLY, and the template's demo-fixture fallback MASKED it (looked like it worked). Surface RPC errors; never silently fall back to fixtures. (stage-seo-store-2)
- **Capture-shape ↔ render-shape contracts fail SILENTLY:** onboarding wrote `site_assets.work` + a broad `services` array while the template read `work_examples` + a slug-keyed `by_service` map — every real client silently got stock images. Verify the WRITER's shape against the READER's shape end-to-end whenever a fallback exists to mask the miss. (stage-svc-2b-rev)
- **Store the relationship, don't re-parse it** — `content_pages.parent_slug` exists because deriving parentage from slug patterns is fragile (primary geos have no subject in the slug). (stage-s4-pages-tree)
- **Slugs freeze at creation** (derive-once on add, never re-derive on rename) — join keys (page slugs, `by_service`, `parent_slug`) stay stable through display renames. Reserved-slug list guards collisions. (stage-seo-map-editor-unification)
- **Lovable auto-commits/pushes each build as `gpt-engineer-app[bot]` with a short lag** — re-fetch before declaring a just-validated build missing from origin. (stage-s4d0)
- **Dual-writer guard [LOCKED]:** any surface writing `template_vars`/`social_links` does read-merge-WRITE-THE-FULL-OBJECT (never partial replace — `updateClientSettings` and raw UPDATEs replace jsonb wholesale) and re-seeds sibling editors' state. (stage-c3-discount, stage-c3-social-links-admin)

## 7. SEO/content system decisions still governing

- **Pages are DATA rows; the template is a generic renderer** — publishing/writing never touches the Lovable project. `seedCoreThirty`/`seedGeoPages` are idempotent (`onConflict client_id,slug ignoreDuplicates`) — re-runs never overwrite edited/published rows. (stage-seo-store-3b, stage-loc-2)
- **`content_jobs` resumable pass model:** `current_pass` = passes COMPLETED (0 fresh, 8 done), pass-3 has `section_idx` sub-progress, every step persists state → resume is free; de-duped job creation; `FOR UPDATE SKIP LOCKED` claim on the cron route. (stage-s4d1)
- **Geo discipline:** `seedGeoPages` SKIPS the primary city (home owns it); geo slugs = frozen location slug (deeper cells `${subject}-${location}`); **deletion BLOCK guards** — can't delete a location with existing geo pages, can't reset geo pages that have supporting children (`parent_slug`) — no silent orphaning. "Never blanket-launch geo before topical authority." (stage-loc-2, stage-seo-tab-reorg, stage-s4d0)
- **Per-service pricing flows into service-page writes only** (PROVIDED CONTEXT price line + "state THAT range only"); price-less services state nothing; `normalizePrice` prefixes `$` on bare numbers. (stage-svc-3)
- **Outbound authority link** = operator-provided URL in `content_pages.external_link`, AI-woven as ONE in-content link; blank = no link, never a hallucinated URL; re-woven from the column on every rewrite. Inbound/backlinks = agency-ops (tracker planned), not a page feature. (stage-seo-outbound-link)
- **SEO input editors live in the SEO tab** (moved OUT of Settings 2026-07-07: services/pricing, competitor URLs, business content, service areas) — single edit surface, same server fns. (stage-seo-tab-reorg)
- **The tier entitlement map** (`entitlements.ts` `tierIncludes`) is the ONLY gate mechanism — one-line map edits, no scattered `tier===` checks. (Note: logs cite "497"; tiers renumbered 2026-07-14 → 297/397/749, gate = 749.) (stage-s4b)
