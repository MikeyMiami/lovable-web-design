- **F-status — RESOLVED (decision 2026-06-14).** Original divergence: runner wrote `status: "stub"`, reply wrote `status: "sent"`, but in stub mode both go through `sendStubSmsWithRetry` (neither hits Twilio) → inconsistent inbox badges + a 1f gap (the reply's hardcoded `sent` would never reflect real delivery/failure). **Decision:** align both callers to a single **`stub`** status in stub mode, and make the 1f status-swap explicitly cover BOTH outbound writes (runner + reply): `stub` → real Twilio delivery/failure status. Folded into `/launch-check` §D (status-swap checkbox) + spec §12 (materialization bullet). *(Chose `stub` over `queued`: unambiguous stub-mode marker — `queued` is also a real Twilio status, so it'd blur stub vs genuinely-queued; and it's the minimal change since the runner already writes `stub`.)*
  - **Tiny 3c follow-up — LANDED:** `reply.functions.ts` now passes `status: "stub"` to `insertOutboundMessageRls` (both callers match). Confirmed in the SQL end-state (both rows `status='stub'`). At 1f the single status-swap moves both to real Twilio delivery/failure status.

## 🟥 Publish blocker — 2 pre-existing CRITICAL findings (NOT 3c; assessed → Stage-3.5 §A)
Publish (and thus the real cron walk) is blocked by two pre-existing critical security-scan findings, unrelated to 3c:
1. **`clients_anon_select_sensitive_fields`** — the anon SELECT on `clients` is row-level only (`USING status='active' AND deleted_at IS NULL`), exposing ALL 27 columns to anon. **This is foundation open-item #2** (`foundation-schema-snapshot.md`: "exposes all 27 columns … fix later via public view / column GRANTs") — the scan now forces it. Architecture requires anon read ONLY the marketing-site public/presentational columns (per `scratch-foundation` §"clients anon read"), never `call_forwarding_number` / `twilio_messaging_service_sid` / `clients.email` / `allowed_origins`.
2. **`storage_objects_no_policies`** — `storage.objects` has no RLS policies; `scratch-foundation` §9 specifies **public-assets** (public read) + **client-assets** (client_id-scoped via `(storage.foldername(name))[1]::uuid IN user_client_ids`). The policies were specified but not applied.
Both are §A (tenant-isolation / RLS correctness) golden-master-proving material → **Stage-3.5 pre-freeze §A security step** (recommend pulling forward, since they gate publish + the cron walk + all published testing). Full assessment in the turn's Claude Code response. NOT 3c's fault.
